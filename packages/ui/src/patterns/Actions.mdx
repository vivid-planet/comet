## Emphasis

- **One primary button per view** — a page, a dialog or a form — for the action most users take next: "Publish", "Save changes", "Place order".
- **Secondary buttons** for the actions next to it, such as "Preview" or "Cancel".
- **Ghost buttons** for less important or repeated actions, such as in a toolbar or a dense list.

If several actions seem equally important, the view probably does too much: split it, or move the rarely used actions into secondary buttons.

## Labels

- Start with a verb and name the object when it isn't obvious: "Delete product", not "Delete" or "OK".
- Use sentence case and keep it short: two or three words.
- A button's text and its icon say the same thing. The icon is decorative, so the text must stand on its own.

## Icon buttons

<Canvas of={ActionsStories.RowActions} />

Use an `IconButton` only where space is tight and the icon is widely understood, such as a pencil for editing or a trash can for deleting. Its `label` names the action for screen reader users; repeat the object in rows of the same actions, for example `label="Delete Linen shirt"`, so every button has a distinct name.

```tsx
<IconButton label={`Delete ${product.name}`} size="small" onClick={() => deleteProduct(product.id)}>
    <Icon name="delete" />
</IconButton>
```

The icon button doesn't show its label as a tooltip yet. Prefer a `Button` with text wherever it fits.

## Destructive actions

There is no danger variant yet. Until then, label a destructive action with its consequence, such as "Delete product", give it a `secondary` button, and ask for confirmation before anything that can't be undone.

## Disabled buttons

A disabled button doesn't say why it's disabled. Prefer keeping it enabled and explaining what's missing when the user activates it, for example by validating the form on submit. If a button must be disabled, explain why next to it, and use `focusableWhenDisabled`, so keyboard users can still reach it.

## Buttons and links

A button triggers an action on the current page; a link navigates to another one. Use a link for navigation even if it should look like a button: screen readers and browsers treat links differently, for example when opening them in a new tab. `Button` always renders a `<button>`.
